# 2026年度3Q 記事チーム進捗管理

月曜のチーム週次MTGと火曜のPC局チーフマネージャーMTGで使う、目標・戦略・週次進捗の共通ページ。

公開ページ: https://usukura-p.github.io/conversion-design-q3-2026/

## 毎週の使い方

金曜〜日曜のどこかで、臼倉さんがAIに「更新して」と依頼する。その都度、AXADの数値・新しくリリースされた記事・記事URL・次の月曜の報告週を更新する。定期実行はしない。具体的な手順と保全ルールは [UPDATE_WORKFLOW.md](UPDATE_WORKFLOW.md)。

月曜は前週月曜〜日曜にリリースした記事を振り返る。週ごとのプルダウンを開いて、チーム報告・記事の振り返り・個人報告を確認する。火曜の約5分の報告では、上部の目標・グラフとチーム報告を中心に使う。

チーム・個人の報告は各欄の「この欄を保存」で共有する。更新者の入力は不要。記事名をクリックすると記事を別タブで開き、横の矢印で「評価・結果・考察・ネクスト」を開く。評価は◯・△・×から手動で選び、閉じた記事行でも確認できる。評価・結果・考察・ネクストは「この振り返りを保存」でまとめて共有する。未保存の入力は端末の下書きに残る。以前のブラウザ内の下書きがある場合は「この端末の下書きを取り込む」で確認してから共有する。元の下書きは保持され、ダウンロードにも含まれる。

## 集計

- 売上KGIはPC局全体。9月554,427,123円、10月715,000,000円、11月800,000,000円、12月885,000,000円。
- Meta実質CVRは記事ごとのCV÷クリックの単純平均。消化額の足切りなし。記事名に「貸し」「修正」を含む記事は除外。「新規」「改修」は対象。DIO ★033（`axad-release-row-205`）もユーザー確認済みの修正記事として除外する。
- クリック0／未配信は算出不可として平均から除外。0CV・クリックありは0%として含む。
- 3Q累計CVRは10/1〜12/31リリース記事。記事ごとの観測はリリース日〜集計日。
- 制作成果グラフは各週までにリリースした記事の累計平均。各週末までのMeta原数で計算する。9月参考は9/1から、3Qは10/1から対象を累積する。
- 記事別パフォーマンス表は全媒体の原数・派生指標と、右端にMeta実質CVRを表示する。実質CVRは全媒体CV÷全媒体クリック、Meta実質CVRはMeta CV÷Metaクリック。合計行はそれぞれの媒体範囲の原数を合算して再計算し、目標指標の記事単純平均とは計算方法が異なる。
- 記事表は `public/article-performance.json` の同時取得した全媒体＋Meta原数を使用し、取得時刻を表の上に表示する。KPI・グラフは `public/axad-data.json` と保存済み週次スナップショットを使用する。記事表の更新で保存済みKPI・過去週を上書きしない。
- 個人立案は寒竹・青木・中川各3件（優先度会議日）、チーム配信9件（配信日）。いずれも3Q累計。
- 9月比較1.65%、2Q参考2.22%は新条件で再集計。根拠と照合結果はAUDIT.md。
- 未入力は未入力として表示し、架空の実績や過去週を作らない。

報告・施策の最新週保存時に数値をスナップショット化する。記事の振り返り保存は既存数値を保持する。過去週の文言修正で当時の数値を書き換えない。複数人の編集が重なる場合は下書きを残し、衝突を解決して保存する。

## 構成

public/はGitHub Pages、server/は匿名保存API。保存先はこのrepoのdata/state.jsonに限定。認証情報はブラウザ・Gitには置かない。データはGit履歴から復元できる。

コード開発・デプロイはcodex/3q-dashboardブランチ。検証: `node --test tests/*.test.mjs server/*.test.mjs`。

保存前に最新の共有状態を読み、対象の欄だけを統合する。同じ欄の競合は自分・最新の内容を明示的に選ぶ。失敗時は入力を保持し、同じ内容で再送する。下書きはタブごとに保管し、別タブ・前回の下書きは明示的に取り込むかダウンロードできる。グラフと週次履歴は共有済みの状態を表示する。

集計対象外の記事は、週の「集計対象外」プルダウンに参考として残す。正式名・ID・URL・原数・保存済みの評価や振り返りは保持し、KPI平均・制作成果グラフ・記事表の合計には含めない。参考表には合計行を設けない。
